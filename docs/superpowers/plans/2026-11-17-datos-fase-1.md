# Datos (Fase 1) — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Llenar la base de datos con cartas (FUT.GG), precios PC (EasySBC + lo que Camilo ve en la web app de EA) y el club real de Camilo (extensión propia de solo lectura), y mostrarlo en la pantalla Mi club.

**Architecture:** Paquete nuevo `fcsl_api.ingest` con un cliente HTTP prudente (1 petición/s, caché en disco, se detiene ante 403/429) y dos adaptadores puros (FUT.GG → cartas, EasySBC → precios) con su comando de sincronización. Endpoints `/import/*` (con token) que reciben lo que la extensión observa en la web app de EA. Extensión Chrome MV3 que intercepta pasivamente respuestas de la web app (nunca hace peticiones al mercado). Endpoint `GET /club` y pantalla Mi club.

**Tech Stack:** lo existente (Python 3.13/uv, FastAPI, SQLAlchemy/Alembic, Postgres 16 en :5544, Next.js/Vitest) + `httpx` como dependencia de runtime; extensión en TypeScript compilada con `esbuild`, tests con Vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-fc-squad-lab-design.md` (§4 actualización 2026-11-17, §6, §7 Fase 1). Fuera de este plan: retos de SBC desde la extensión y pantalla de reto (Plan 3), importación activa del club completo usando servicios internos de la web app (Plan 3), solver sobre datos reales (Plan 3).

## Global Constraints

- Fuentes externas: **≤ 1 petición/s por fuente**, caché en disco (`apps/api/var/cache/`, git-ignorado), parar la sincronización ante **403/429** y conservar los datos previos, **nunca** saltarse protecciones anti-bots (Cloudflare, CAPTCHA). User-Agent configurable (`FCSL_HTTP_USER_AGENT`).
- FUT.GG: `GET https://www.fut.gg/api/fut/players/v2/27/?page=N` (30 por página, `next`, `total`). EasySBC: `GET https://api-fc27.easysbc.io/players?v2&page=N` con cabeceras `Platform: PC` y `Origin: https://www.easysbc.io` (24 por página, `totalPages`).
- Clave común: `resource_id` (EA) = `eaId` (FUT.GG) = `resourceId` (EasySBC). `asset_id` = `basePlayerEaId` (FUT.GG) = `assetId` (EasySBC).
- Plataforma de precios: **`PC`**.
- La extensión **solo lee**: intercepta respuestas que la web app ya recibe; nunca llama a endpoints de EA por su cuenta.
- Importación protegida con token: cabecera `X-FCSL-Token`, valor en env `FCSL_IMPORT_TOKEN` (sin token configurado → 503 en `/import/*`).
- Precio efectivo de una carta (PC): la observación de la sesión de EA (`source="ea-session"`) si tiene < 24 h; si no, EasySBC `market`; si no, EasySBC `sbc`; si no, nulo.
- PEP8 OR-Tools API si se toca el solver (no debería). Commits sin trailer de co-autor. `make check` en verde al final de cada tarea. Textos de UI en español.

## Review Focus

1. **Fuente caída o bloqueando (403/429/timeout)** → la sincronización se detiene, registra el error en `sync_runs` y los datos anteriores siguen intactos. → Task 1 y 2.
2. **Importar dos veces lo mismo** (mismo club, mismas observaciones) → idempotente, sin duplicados. → Task 4.
3. **Carta del club que no está en `cards`** (promo nueva) → se guarda igual y Mi club la muestra con "sin datos de carta". → Task 4 y 6.
4. **Token ausente o incorrecto** → 401 (o 503 si el servidor no tiene token configurado), nunca escribe. → Task 4.
5. **Respuesta de EA con forma inesperada** → la extensión no rompe la web app (try/catch, nada se lanza dentro del interceptor) y no envía basura. → Task 5.
